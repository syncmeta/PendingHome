# 数据迁移 —— 把试验台虚拟机里的 HA 整个搬到实体机

目标：**搬完之后不用重新登录米家、不用重配集成、不用重建实体。**
打开新机器的 HA，看到的就是原来那一套：258 个实体、原来的名字和房间、
原来的账号、连鼠标桥用的那个长期令牌都还有效。

对应主流程的 [阶段 5](README.md#阶段-5--把虚拟机里的数据搬过来)。

---

## 先摸清楚：数据到底在哪

去虚拟机里实地看过（`limactl shell ha-lab`），结论是：

**HA 的全部状态就是一个目录：虚拟机里的 `/opt/ha/config`（容器内挂成 `/config`）。**

Mac 上 `ha-lab/homeassistant/config/` 那个目录**是空的占位目录，不是运行时数据** ——
当初刻意不让 HA 的 SQLite 数据库落在跨虚拟机的共享挂载上（virtiofs 的文件锁不可靠，
容易写坏库）。所以要搬的东西**全在虚拟机内部**，Mac 上没有副本。

实测这个目录 **13MB**，长这样：

| 路径 | 是什么 | 搬不搬 |
|---|---|---|
| `.storage/` | **重点。** HA 的真正状态都在这（2.4MB） | ✅ 必须 |
| `.storage/core.config_entries` | 装了哪些集成、每个集成的配置（含 Xiaomi Home 那条） | ✅ |
| `.storage/core.entity_registry` | 258 个实体的身份、实体 ID、你起的名字 | ✅ |
| `.storage/core.device_registry` | 设备清单、归属的房间 | ✅ |
| `.storage/auth` | **HA 账号 + 长期访问令牌**（`root:root 0600`） | ✅ |
| `.storage/xiaomi_home/cert/` | **米家的设备证书和私钥 —— 免重新登录的关键** | ✅ |
| `.storage/xiaomi_home/miot_config/` | 米家账号信息、选了哪个「家」和哪些房间 | ✅ |
| `.storage/xiaomi_home/miot_specs/` | 设备规格缓存（当初拉这个超时过，带过去省事） | ✅ |
| `custom_components/xiaomi_home/` | Xiaomi Home 集成本体（2.6MB，不是官方内置的） | ✅ |
| `configuration.yaml` 等 | 主配置、自动化、脚本、场景 | ✅ |
| `home-assistant_v2.db` | 历史数据（recorder，SQLite，824KB） | ✅ 可选 |
| `.cache/brands/` | 集成图标缓存（3MB，会自己重建） | ✅ 顺带 |
| `home-assistant.log*` | 日志 | ❌ 排除 |
| `.ha_run.lock` | 记着旧机器的 pid，搬过去只会误导 | ❌ 排除 |
| `deps/` | 集成的 Python 依赖 —— **实测是空的**，所以没有跨架构问题 | （空） |

## 为什么「整个目录打包搬走」是对的做法

**方案 A（采用）：文件系统级整目录搬迁。**
HA 的凭据就是 `.storage` 里的普通文件，跟机器硬件没有任何绑定关系 ——
没有机器指纹、没有 TPM、没有按 MAC 派生的密钥。原样搬过去就继续认。

**方案 B（不采用）：HA 界面里的「备份」功能。**
它主要是给 HA OS / Supervised 用的，容器版做出来的备份还得手工拆包才能还原，
中间多一层格式转换，反而更容易漏东西。既然拿得到文件系统，直接搬更直接、更好验证。

**方案 C（不采用）：重装一遍再重新登录米家。**
就是这次要避免的事 —— 得重扫码、重选家、258 个实体的 ID 会重新生成，
`mouse-bridge/config.json` 里那两个 `light.*` 实体 ID 大概率跟着变，得重配。

### 跨架构（arm64 → x86_64）要紧吗

**不要紧，实地确认过了。** 试验台是 Apple 芯片上的 arm64 Debian，新机器是 x86_64。
但 `/config` 里没有任何架构相关的东西：

- `deps/` 是空的（没有编译出来的 Python 扩展）
- `.storage/*` 全是 JSON 文本
- `custom_components/xiaomi_home/` 是纯 Python
- `home-assistant_v2.db` 是 SQLite，文件格式本身就跨平台跨字节序
- HA 的镜像是多架构的，`ghcr.io/...:stable` 在 x86_64 上会自动拉到 amd64 那份

### 版本只能升不能降 ⚠️

源机器现在是 **HA 2026.8.1**（`config/.HA_VERSION` 里写着）。

HA 每次启动会把 `.storage` 里的数据结构往当前版本迁移，**这个过程是单向的**。
拿一个比源更旧的 HA 去开这份数据，轻则集成加载失败，重则把 `.storage` 写坏。

所以恢复之后**第一次启动务必指定同版本**：

```bash
HA_IMAGE=ghcr.io/home-assistant/home-assistant:2026.8.1 ~/ha-home/ha-up.sh
```

验证一切正常之后，再去掉 `HA_IMAGE=` 跑一次 `ha-up.sh` 升到 `stable`。
`02-restore.sh` 会自动从包里读出版本号，把这条命令替你拼好打印出来。

### 为什么打包前要停 HA

recorder 用 SQLite 的 WAL 模式，运行时 `home-assistant_v2.db-wal` 里攒着还没归并
进主库的事务（实测那个文件有 4MB，比主库还大）。容器正常停止时 HA 会关库、
把 WAL 归并、删掉 `-wal`/`-shm`，那之后打包才是一个一致的快照。

停机大约 30 秒，脚本会自动停、自动起回来，并且**打印数据库是否干净落盘**。

急着不想停机的话有 `--hot`，但那样搬过去的历史数据库可能不一致（HA 一般能自愈，
坏情况下会丢一点最近的历史）—— **凭据和实体注册表不受影响**，那些是 JSON 文件、
写入是原子替换的。

## 操作步骤

### 1. 导出（在 Mac 上）

```bash
cd ~/Untitled/PendingHome/ha-home
./migrate/01-backup-from-lab.sh
```

它会：停 HA → 确认数据库干净落盘 → 打包 → 校验包能读 → **逐项点名关键内容**
（米家证书、账号、令牌、实体注册表在不在，实体数量对不对）→ 起回 HA。

实跑输出长这样（2026-08-11 真的跑过一次）：

```
    HA 版本 2026.8.1
==> 停 Home Assistant（打完包自动起回来）
    数据库已干净落盘
    大小 2.6M   sha256 4878ac...
    ✅ 集成清单（含 Xiaomi Home 那条）
    ✅ 实体注册表（那 258 个实体的身份）
    ✅ HA 账号 + 长期令牌（令牌搬过去继续有效）
    ✅ 米家设备证书（免重新登录的关键）
    实体注册表条目数：258
```

可选参数：
- `--no-history` 不带历史数据库（图表从零开始，其余一切照旧）
- `--hot` 不停机打包
- `--out <路径>` 指定输出文件

### 2. 传过去

```bash
scp migrate/ha-config-*.tgz <用户名>@homeassistant.local:~/
```

⚠️ **这个包里有凭据**（米家证书私钥、HA 账号、长期令牌）。别进版本库、别发群里、
别丢网盘。用完新机器验证通过后，Mac 上这份可以留一份当后路，但要放在只有你能读的地方。

### 3. 恢复（在新机器上）

```bash
./ha-home/migrate/02-restore.sh ~/ha-config-*.tgz
```

它会：校验包 → 停掉可能在跑的 HA → **把已有的 `/opt/ha/config` 挪到旁边留底**
（不删）→ 带权限解包 → 点名检查落地结果 → 打印第一次启动该用的命令。

### 4. 验收

按主流程 [检查点 D](README.md#阶段-6--起-home-assistant) 那四条一条条勾。
最要紧的两条：**Xiaomi Home 没要求重新登录**，**点一下吸顶灯真灯有反应**。

## 搬完之后可能要顺手改的三处

1. **鼠标桥的 `ha_url`**
   试验台上是 `http://192.168.1.16:8123`（虚拟机的局域网地址）。新机器上 HA 就跑在
   本机，`mouse-bridge/install.sh` 会自动改成 `http://127.0.0.1:8123` —— 最短路径，
   也不依赖 mDNS 或者 DHCP 给的地址。

2. **HA 里的地理位置**
   现在存的是 `52.37, 4.89`（阿姆斯特丹）—— HA 的默认值，当初引导时没改。
   日出日落、天气之类的都会不准。设置 → 系统 → 常规 里改成你实际的位置。
   跟迁移无关，顺手提一句。

3. **米家集成里存的回调地址**
   配置里记着 `http://homeassistant.local:8123/api/webhook/...`。日常运行用不到它
   （靠的是已经签发好的证书），只有**重新走一次米家登录**时才会用。
   新机器正好就叫 `homeassistant.local`，所以这条反而更对了。

## 万一没搬成

`02-restore.sh` 不删任何东西，原有的 `/opt/ha/config` 会被挪到
`/opt/ha/config.bak-<时间戳>`。回退就是把它挪回来。

更重要的是：**试验台虚拟机在整个过程中原封不动**（导出只是读，唯一的动作是停一下
再起回来）。新机器上怎么折腾都不影响它。所以新机器验通、稳定跑几天之前，
**先别删虚拟机**，`limactl stop ha-lab` 关掉就好。

⚠️ 但**别让两台同时开着**：同一个米家账号的设备证书在两处同时用容易互相踢掉，
而且两台都往局域网广播 `.local` 名字会打架。
