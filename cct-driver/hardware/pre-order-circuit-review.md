## 🟡-3 的评估结论:**不动**(风险高、收益低)

机长要求"先看一眼能不能低风险地把那块铜扩开,会牵动已布通的功率段就别动"。量完之后结论是不动,三条理由:

1. **能低风险扩的那点扩不动指标。** 覆铜矩形是 `rect(101.5, 112.0, 129.0, 124.3)`。
   - 向下:下一行就是 F1 的上排夹片焊盘(y = 125.61),扣掉间距只剩约 0.7mm → **+19 mm²**
   - 向右:板框在 x = 130.1,扣掉板边间距只剩约 0.5mm → **+6 mm²**
   - 合计 **+25 mm²(+8%)**。θ 对铜面积是次线性的,这点面积换来的温升改善在 4% 量级 —— 白改。
2. **有意义的扩法要牵动功率段。** 唯一还有空间的方向是**向左**(x < 101.5),
   而 x 100–101.5 已经是 CH1 那一列(列心 x = 92、列宽 16mm)的边界,再往左就是已布通的功率级。
   **按机长划的界限,这个方向不动。** 向上也不行:Q1/Q2 的源极焊盘在 y ≈ 110,
   它们那两条 2.0mm 宽的走线占着 y 110–111,`V24_PROT` 覆铜的下沿就压在 y = 111.0,
   中间只剩 1mm 隔离带。
3. **在底层再铺一片 `V24_FUSED` 会让事情更糟。** D0 区的底层现在是整片 GND(全板 GND 铜 26346 mm²)。
   按 🟡-3 里那两条热路径的估算,**占优的是「顶层铜岛 → 穿过 1.6mm FR4 → 底层大地平面 → 空气」**
   (纵向热阻约 17.5 °C/W)。把底层那块 GND 换成 `V24_FUSED`,等于把散热片正下方的大平面
   换成一块和顶层一样小的孤岛,**恰好把好的那条路径拆掉**。

**所以留给验板实测**:12A 连续满载 30 分钟,热电偶贴 Q1/Q2 的 tab。
温升 > 70 °C 再考虑下一版重排 D0 区的分区边界 —— 那是摆位层面的改动,不是补一块铜。

> 复核后实测:`V24_FUSED` 网的总铜面积改动前后都是 **422.2 mm²**(覆铜填充 304.8 mm²),
> `V24_PROT` 都是 **1129.6 mm²** —— 这一轮**没有动过任何一块功率铜**。

# 🔴 下单前必须改(2 条)

## 🔴-1 USB 自动下载电路接错:Q4/Q5 的发射极接了 GND,应当交叉接到对方那根控制线

**要重出 PCB。** ✅ **2026-08-18 已改并重新验过**(原理图提交 `788e48c`,PCB 与出货文件随后重导)。

### 原理图实测

| 器件 | 脚 | 网络 |
|---|---|---|
| U5(CH340C) | 13 = `DTR#` | `DTR` |
| U5(CH340C) | 14 = `RTS#` | `RTS` |
| R11 | 1 / 2 | `DTR` / `RTS_B` |
| **Q4**(S8050) | **B / E / C** | **`RTS_B` / `GND` / `EN`** |
| R12 | 1 / 2 | `RTS` / `DTR_B` |
| **Q5**(S8050) | **B / E / C** | **`DTR_B` / `GND` / `IO0`** |

两颗管子的**发射极都接 GND**。于是这不是一个逻辑门,而是两个各自独立的反相器:
`DTR#` 高 → Q4 导通 → `EN` 拉低;`RTS#` 高 → Q5 导通 → `IO0` 拉低。

### 正确电路长什么样

Espressif 参考电路(以及所有 DevKitC 衍生板)要的是一个**异或型**的行为:

| DTR# | RTS# | EN | IO0 | 用途 |
|---|---|---|---|---|
| 高 | 高 | **高** | **高** | 正常运行(串口空闲) |
| 低 | 低 | **高** | **高** | 正常运行 |
| 高 | 低 | **低** | 高 | 复位 |
| 低 | 高 | 高 | **低** | 进下载模式 |

(出处:[Espressif's Automatic Reset — Quentin Santos, 2025-05-09](https://qsantos.fr/2025/05/09/espressifs-automatic-reset/);
同一张真值表也见 [espressif/esptool Boot Mode Selection](https://docs.espressif.com/projects/esptool/en/latest/esp32/advanced-topics/boot-mode-selection.html)。)

**"两根线电平相同 ⇒ 两管都截止"这条性质,是靠把发射极接到对方那根线上得到的**
(Q_EN:B←`DTR#`、**E←`RTS#`**、C→`EN`;Q_IO0:B←`RTS#`、**E←`DTR#`**、C→`IO0`)。
把发射极改接 GND,这条性质就没有了 —— **这正是本板的问题。**

### 后果(按 esptool 实际时序逐拍推)

esptool 的 `classic_reset` 三拍是 `DTR=False,RTS=True` → `DTR=True,RTS=False` → `DTR=False`。
CH340C 的 `DTR#`/`RTS#` 是**低有效输出**(WCH CH340 Datasheet v3C 第 3 页引脚表:
"MODEM contact output signal, data terminal ready, **active low**"),所以主机置位 = 芯片脚拉低。

| 拍 | DTR#/RTS# 脚 | 本板 EN | 本板 IO0 | 应该是 |
|---|---|---|---|---|
| ① | 高 / 低 | 低 ✅ | 高 ✅ | 低 / 高 |
| ② | 低 / 高 | 高 ✅ | 低 ✅ | 高 / 低 |
| ③ | **高** / 高 | **低 ❌** | **低** | 高 / 高 |

前两拍碰巧对,**第三拍把芯片重新按回复位并一直按着** —— 而整个烧录过程中 esptool 都不会再动 DTR。
所以**烧录必然失败**。

更要命的是第三拍那个状态就是**串口关闭后的常态**:任何程序关掉串口、或者根本没打开过串口,
`DTR#` 都是高 → `EN` 被钉在低电平 → 板子停机,直到把 USB 拔掉。

**没插 USB 的情况也有风险**:CH340C 是从 `V3P3` 供电的(U5 pin16 VCC 和 pin4 V3 都接 `V3P3`,原理图实测),
只要板子上电它就活着。而 WCH 手册第 5.1 节明写:
> "The **DTR# pin of the CH340G/C/T/K** chip is used as a **configuration input pin before the USB configuration
> is completed**. It can be connected to an external 4.7KΩ pull-down resistor to generate a **default low level**
> during USB enumeration."

也就是说没枚举完之前 `DTR#` 是个**输入**,厂家要你外加 4.7k 下拉才能得到低电平 —— 反过来说**它的默认是高**。
本板 `DTR#` 上挂的是 R11(10k)串到 Q4 基极,基极钳在 0.7V;这条路能不能灌够 Q4 的基极电流,
**手册没给 CH340C 这个内部上拉的具体阻值,查不到,需实测**。
最坏情况:**24V 单独供电时板子也起不来**。

`RTS#` 那一路没有"配置输入"这个说法,是普通输出,空闲(未置位)= 高 → Q5 导通 → **`IO0` 被拉低 →
每次上电都进串口下载模式,永远跑不到应用**。

### 改法(要重出 PCB)

- `Q4.E` 从 `GND` 改接 `RTS`(即 U5 pin14 那个网络);
- `Q5.E` 从 `GND` 改接 `DTR`(即 U5 pin13 那个网络);
- R11/R12 保持 10k 不动。校核:基极电流 (3.3−0.7)/10k = **260 µA**,
  要拉低 `EN` 需要吸 3.3V/R4(10k) = **330 µA** → 需要的 β 只有 **1.3**,S8050 深度饱和 ✅
- **顺带把 C12 从 10µF 换成 1µF**(见 🟡-1,同一封装,只改 BOM),否则改对了电路时序还是不够。

## 🔴-2 GPIO15 自带 45kΩ 内部上拉,导致「复位期间输出关断」这条硬件失效安全**不成立**;每次上电会闪灯

**只改 BOM(R15:100k → 4.7k),不用重出 PCB。** ✅ **2026-08-18 已改**(`R15` = `C23162`,4.7kΩ 0603)。

### 规格书/固件的假设

`netlist-spec.md` §Block D 的行为验证表和 §A2.3b 都写着:

> ESP32 未上电 / 启动中 GPIO15 未定义 / 看门狗复位 → **R15 拉低 → Q6 关断 → `OE_N` 被 R13 拉高 → 12 路高阻 → 自动关灯**

`firmware/cct-driver.yaml` 第 66–70 行也是这么写的:
> "GPIO15 是 strapping 脚。此处安全:经 10k(R14)+ 100k(R15)到地构成弱下拉,启动时读低"

### 手册怎么说

ESP32 Series Datasheet v5.3:

- **Table 3-1 Default Configuration of Strapping Pins**:`MTDO`(= GPIO15)的 Default Configuration 是
  **Pull-up**,Bit Value = 1。同表:GPIO0 Pull-up、GPIO2 Pull-down、MTDI Pull-down、**GPIO5 Pull-up**。
- **Table IO_MUX**(pin 21 = MTDO/GPIO15):`At Reset` = **`oe=0, ie=1, wpu`**、
  `After Reset` = **`oe=0, ie=1, wpu`**。即**复位期间和复位之后内部上拉都是开着的**,
  一直到软件去改它为止。
- 同章注 9:"The drive strength of the internal pull-up (wpu) and pull-down (wpd) is **~75 µA**"
  (等效约 45 kΩ)。

### 算一遍 Q6 到底导不导通

内部上拉 45k → R14(10k) → Q6 基极(钳在 0.7V),R15(100k)分流:

```
Ib = (3.3 − 0.7)/(45k + 10k) − 0.7/100k = 47.3 µA − 7 µA = 40.3 µA
```
(用 75µA 恒流源口径算也一样:75 − 7 = 68 µA,更大。)

Q6 = MMBT3904,hFE 最保守取 40 → 可吸 **1.6 mA**;
把 `OE_N` 拉低只需要 5V/R13(10k) = **0.5 mA**。

**→ Q6 饱和,`OE_N` ≈ 0.1V,两片 74HCT245 在整个启动过程中是使能的。**
余量 3×(hFE=40)到 8×(hFE=100~300 的下限)。**这不是边界情况,是确定会发生。**

### 使能之后 245 的 A 脚是什么电平

同一张 IO_MUX 表,12 路 PWM 脚复位后(`After Reset`)的状态:

| 通道 | GPIO | After Reset | 245 输出 | MOS |
|---|---|---|---|---|
| CH1_CW | 4 | `ie=1, wpd` | 低 | 关 |
| **CH1_WW** | **5** | **`ie=1, wpu`** | **高** | **全导通** |
| CH2_CW | 13 | `ie=1, wpd` | 低 | 关 |
| **CH2_WW** | **14** | **`ie=1, wpu`** | **高** | **全导通** |
| CH3_CW | 16 | `ie=1`(无上下拉) | **悬空 → 不确定** | 不确定 |
| CH3_WW | 17 | 该行 pdftotext 没取到,**查不到,需实测**(同族的 MTMS/MTDO 都是 wpu) | — | — |
| CH4_CW / CH4_WW | 18 / 19 | `ie=1`(无上下拉) | 悬空 → 不确定 | 不确定 |
| CH5_CW | 21 | `ie=1`(无上下拉) | 悬空 → 不确定 | 不确定 |
| **CH5_WW** | **22** | **`ie=1, wpu`** | **高** | **全导通** |
| CH6_CW | 23 | `ie=1`(无上下拉) | 悬空 → 不确定 | 不确定 |
| CH6_WW | 25 | `oe=0, ie=0`(整个脚关掉) | 悬空 → 不确定 | 不确定 |

另外 6 路 A 脚悬空 —— 74HCT245 的 CMOS 输入悬空,输出电平不确定,还会自激和多耗电
(这一条规格书自己在 §Block D 对 U7 的 A5–A8 讲过,但没意识到 12 路 PWM 在复位期间同样悬空)。

### 闪多久

| 段 | 时长 | 依据 |
|---|---|---|
| `EN` 的 RC 上升(3.3V 到位 → EN 过 VIH) | **138 ms** | R4=10k、C12=10µF、VIH = 0.75×3.3 = 2.475V → t = −τ·ln(1−2.475/3.3) = 1.386τ |
| ROM bootloader + ESP-IDF 启动 | 约 250–600 ms | 经验值,**未实测** |
| ESPHome 走到 `switch` 组件 setup、把 GPIO15 驱动为低 | 再几十 ms | — |
| **合计** | **约 0.5 – 1 s** | |

**每次上电、每次按 RESET、每次看门狗复位,三路暖白满亮约一秒。**
`cct-driver.yaml` 的 `on_boot priority:-100` 那段注释("避免上电闪光")说明设计意图是对的,
但它只能管**固件跑起来之后**,管不了它自己启动之前的这一秒。

### 改法(只改 BOM)

**R15:100kΩ(C25803)→ 4.7kΩ(C23162,`R52`/`R53` 已在用,不新增料号)。**

| 场景 | 校核 | 结果 |
|---|---|---|
| GPIO15 内部上拉(最坏按 75µA 恒流) | R15 在 0.7V 时要吸 0.7/4.7k = **149 µA** > 75 µA | **Q6 铁定截止** ✅ |
| ESPHome 把 GPIO15 驱动到 3.3V | Ib = (3.3−0.7)/10k − 149µA = **111 µA**,×hFE 40 = 4.4 mA ≫ 0.5 mA | **深度饱和** ✅ |
| Q3(总断路)钳 `OE_B` 到 0.1V | 要吸的电流 (3.3−0.1)/10k = 0.32 mA,Q3 能吸 25–76 mA | **硬件仍压得过固件** ✅ |

## 🟡-1 `C12` = 10µF 让 EN 的复位延时到 138ms,自动下载时序对不上 ✅ 已改

C12 = 10µF/25V(`C15850`),R4 = 10k → τ = 100 ms,EN 爬到 VIH(2.475V)要 **138 ms**。
esptool 在释放 `EN` 之后只等 **50 ms** 就把 `IO0` 放掉。50 ms 时 EN 只有
3.3×(1−e^(−0.5)) = **1.30 V**,芯片还没出复位 → 等它真出复位时 `IO0` 已经是高 → **进不了下载模式**。

Espressif 硬件设计指南给的是 R=10k / **C=1µF**(τ=10ms,13.8ms 就过 VIH < 50ms ✅)。

**改法**:C12 → **1µF/50V X7R 0805(`C28323`,嘉立创基础库)**,**同封装,只改 BOM**。和 🔴-1 是同一次修改里的事。
选 50V 档而不是 25V:同封装、基础库、不额外收换料费,而且 3.3V 偏置下的直流偏置衰减更小 ——
有效容量约 0.95µF → τ = 9.5 ms,`EN` 在 **13.2 ms** 过 VIH,仍然远小于 esptool 等的 50 ms。
上电复位方面 1µF 仍然给出 13.8ms 的延时,足够(ESP32 只要求 3.3V 稳定后 EN 才拉高)。

## 🟡-2 母线电解电容的纹波电流大于额定值(量级 1.5–2×)

**PWM 波形**:`cct-driver.yaml` 第 12 行 `pwm_frequency: 19531Hz`;每对 CW/WW 有
`phase_angle: 0deg / 180deg`(第 82、92 行等),所以 6 路 CW 同相、6 路 WW 反相。

**母线交流分量**(满载 12A,每支路 1A):

- 占空比 D ≤ 0.5 时,CW 组和 WW 组不重叠 → 母线是 6A 的方波,基频 2×19.531k = **39.06 kHz**
- `I_ac,rms = 6·√(2D − 4D²)`,**在 D = 0.25 取最大 = 3.0 A rms**
- D = 0.5 时两组正好接上,母线恒定 6A,交流分量 **0** ✅(180° 错相这一手是有效的)

**这 3.0A 由谁承担**:线缆感抗 2πfL(L 按 1–3µH 估,**未实测**)= 0.245–0.735 Ω;
11 颗 100µF 电解(C1–C5 + C16/18/20/22/24/26)并联的 ESR 约 0.03–0.07 Ω;
C45/C46 两颗 4.7µF 陶瓷在 39kHz 的阻抗是 0.85 Ω,**在这个频率上基本不起作用**。
→ 交流电流的 **75%–95% 走电解**,按路径电阻加权,直接挂在母线上的 C1–C5 拿大头,**每颗约 0.3–0.4 A rms**。

**额定值**:`C2836439` = KNSCHA **RVT100UF50V67RV0040**,立创页面标
**纹波 146 mA @ 120Hz**、寿命 **2000h @ 105°C**、D8×L10.2mm。
高频修正系数按常规 ×1.4 折算到 40kHz ≈ **205 mA**。

→ **0.3–0.4 A vs 0.205 A ≈ 1.5–2.0×**。不会当场坏,但罐体温升按功耗比是设计值的 2–4 倍,
在 2000h/105°C 这个寿命档上会明显缩短寿命。

**这条依赖三个我没实测的量**:线缆电感、这颗电解的高频 ESR、电流在 11 颗电解之间的实际分配。
**验板动作**:满载 12A、把某一对通道调到 25% 占空比(最恶劣点),用热像仪或热电偶量 C1–C5 罐体温度,
同时用电流钳量一颗电解的支路电流。若确认超标,**换一颗同 8×10 封装、低 ESR/长寿命的 100µF/50V,只改 BOM**。
