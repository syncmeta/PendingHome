# PCB 布局指导(v2)

板框 **130mm(宽)× 164mm(高)**,原点左上角,单位 mm。2 层,1oz。
**文件方向 = 上墙安装方向** —— 接线端子在下边,传感器/调试接口在上边。
**所有元件顶层单面贴装**;底层只有覆铜、走线与缝合过孔。

> **这一版是重做的,不是改的。** v1 那块 110×145 的板子没有楼层规划:摆位来自
> `gen_pcb.py`,布线来自自动布线器(`cct.dsn`/`cct.ses`)加 20 个 `gen_route_repair*.py`
> 一轮轮打补丁。人类看着实物说的四条 —— 布局走线乱、入电电路在最中间、丝印标号对不上、
> 元件摆放没对应电流和逻辑走向 —— 本质上都是「先布线后规划」的必然结果。
> v2 先有 [`floorplan-v2.md`](floorplan-v2.md)(电流往哪走、元件摆哪儿),再有摆位和布线,
> 而且**全部由可复跑的脚本生成**,不再有任何手改。

> ⚠️ **还差两条真断路,暂不能下单。** 当前实测(`kicad-cli pcb drc` 全量):
> **DRC 错误 0、短路 0、走线交叉 0、网表与原理图 525 条零差异、位号歧义 0 处、隐藏 0 个**;
> 未连接 9 条,其中 7 条是覆铜分片(电气上通,靠底层地平面),
> **真断的只有 `RT_CLK` 和 `V24_BUS` 那两条**。逐条原因与取舍见文末第八节。

## 一、跑法(顺序不能乱)

```sh
KP=/Applications/KiCad/KiCad.app/Contents/Frameworks/Python.framework/Versions/Current/bin/python3
cd hardware
$KP gen_pcb_v2.py          # 摆位:从空板重建,板框/安装孔/天线禁区/元件就位/焊盘赋网络
$KP gen_silk_v2.py         # 丝印功能标注(要在位号归位之前,好让位号躲开它们)
$KP gen_silk_refdes_fix.py # 位号避障归位
$KP gen_route_v2.py        # 布线 + 覆铜 + 地平面缝合(自带 DRC 与未连接统计,约 40 秒)
$KP gen_gnd_stitch.py      # 按**实际填出来的铜**给地岛补缝合过孔、清掉悬空的(要在覆铜之后)
$KP gen_dfm_fixes.py       # U2 热过孔 / EP 锡膏 / J2 定位孔
$KP gen_mask_dam.py        # J2 阻焊桥加宽
$KP verify_netlist_v2.py   # ⭐ 网表与原理图逐条比对,必须零差异
$KP check-floating-pads.py # ⭐ 全板浮脚体检,必须全绿(判据见第八节,DRC 抓不到这一类)
```

每一步都幂等,**实测复跑过一遍逐项比对**:走线 1233 段、过孔 566 颗、板级丝印文字 58 条
两轮**逐字节一致**(除 uuid)。唯一会变的是覆铜的**填充多边形顶点次序** ——
那是 kicad-cli 每次重填时自己排的,DRC 结果完全一样。
所以**别拿整份文件的 md5 去判断有没有坏**,会误判;要比就比走线/过孔/文字这三类。

### 为什么三个接口不摆在一起(2026-08-17 重排)

一开始 J9/J10/J11 三个接口全在右上角,而它们伺候的 MCU 在左上角 —— **8 根信号要
横穿约 90mm,穿的正是全板最挤的那一块**。这违反楼层规划自己的原则(器件压在它服务的
对象身上:驱动器压在它驱动的那几列上,连接器同样该靠近它通信的那几个脚)。

重排之后:

- **J11(干接点)整块搬到 ESP32 右边**,连它那 12 颗串阻 / 上拉 / 消抖一起 ——
  四路开关信号全程本地,只走十几毫米
- **J10(UART)从 x=94 挪到 x=74** —— 单根 70mm → 45mm
- **J9(I2C)留在右上角不动** —— 它除了 MCU 还要往下喂 D0 里的 U1(电流检测),
  留在右边那一路才短。**这是有意的不对称,不是漏改。**

代价:CC 下拉 R9/R10 被挤出 J2 正下方(见第五节 Type-C 那一条),
Type-C 支撑孔 H3 从 (58,9) 挪到 (61,5)。板框一个字没动。

## 三、布线是怎么做出来的(三层办法,由粗到细)

1. **成束规划**(12 路 PWM、8 根接口信号、12 根栅极):这些线是一束,必须一起排车道。
   规则都是「车道 y 按目标 x 单调分配」,于是同一束内一根都不交叉。
2. **`corridor()` / `auto()`**:短距离两点连线。候选拐法有限且按固定顺序枚举,
   逐段查过间距才落笔;走廊位置自己密扫,不吃手写的常数(摆位一动那些常数就全废)。
3. **`maze()` —— A* 迷宫布线**(两层,0.25mm 栅格):上面两层都试不出来时兜底。
   把已有的铜栅格化成障碍图搜路径。**它不是自动布线器**:一次一条线、不拆别人的线、
   不迭代重布、走不通就记账报出来。

**三层都走不通的,脚本会逐条打印出来并指名道姓报出挡路的是谁** —— 一条都不硬塞。

## 四、层分配(读代码前先读这段)

|  | F.Cu(顶层) | B.Cu(底层) |
|---|---|---|
| 逻辑区 y 0–63.5 | 信号 + GND 覆铜 | 信号 + GND 覆铜 |
| 脊椎带 y 65–77 | V24_BUS 覆铜**不断** | 同一片铜,每列让出 6mm 信号车道 |
| 通道列 y 78–129 | 器件间短连线 + MOS 漏极铜面 + 功率地 | 五条竖向干线 + GND 覆铜 |
| 底部带 y 130–147 | GND(列与列之间的空当) | 每列三条竖线下到端子 |
| 入电区 D0 | V24_PROT / V24_FUSED / V24_IN | GND 覆铜 |

**一列之内的底层车道**(相对列心 cx),六列一模一样:

    栅极 CW  cx−7.2 │ CHn_VOUT cx−5.4(2.6mm)│ 漏极 CW cx−2.0
    漏极 WW  cx+2.0 │ 栅极 WW  cx+7.2        │ 其余是 GND 覆铜

**为什么 GND 回流在顶层、漏极在底层**:MOS 的源极焊盘就落在通道列里,顶层那一片功率地
直接把十二个源极焊盘串起来一路汇到底部带;而十二条漏极是**竖着**穿过这条带的,
放到底层就与它天然不打架。

### 四条成束规划的信号(单根去找缝一定互相堵死)

1. **12 路 PWM**(U4 → U6/U7 的 A 侧输入):底层竖下来 → 顶层横向车道 → 顶层竖下去。
   车道 y **按目标 x 从右到左依次下移**,于是每根线最后那一竖只会经过比自己更靠右的
   车道所在的 x,而那些车道早就拐走了 —— 一根都不交叉。
   (一根根找缝试过,只布通 3 根。)
2. **10 根横穿逻辑区的信号**(干接点 4 + I2C 2 + UART2 2 + USB 串口 2)回 U4:同一套规矩,
   顶层车道带在 **y 23.25–29.55**。为腾出它,A1 那排去耦件下移到 y=30.8、SW1/SW2 到 35.0、
   PWM 车道带整体下移 1.3。

   **车道间距 0.70 是量出来的,不是拍的**:每根车道在源头那一端都有一颗过孔,而更靠上的
   长车道会从这颗过孔头顶横过去,所以下限 = 过孔半径 0.35 + 间距 0.205 + 线半宽 0.125
   = 0.68,取 0.70。10 根 = 9 × 0.70 = 6.30mm,上下各留 0.55 给 U4 的焊盘和那排去耦件。

   两条**从右边回 U4 的信号一律进这条车道带**,不要各走各的直线 —— U0TXD/U0RXD 原先
   走直线,干接点搬过来之后正好从它中间穿过,一次顶掉六条本地连线。车道带存在的意义
   就是把「横向穿越」这件事集中到一处、排好序。

   ⚠️ U0TXD/U0RXD 的目标脚在 U4 的**上排**(y=3.60),照常「到目标 x 就竖上去」会
   直接短在下排的 SW_IN3/SW_IN4 上(上下排同一个 x)。这两根到 U4 右边(x 28.6/29.4)
   上底层、贴着上板边横过去,在自己脚正上方才冒头。
3. **12 根栅极信号**:从驱动器出来先走脊椎那条 6mm 车道下行,出脊椎后才向本列两侧张开 ——
   **脊椎以下没有一根线跨列**。
4. **J2(Type-C)的 A/B 双面触点**:见第五节最后一条。

### 「内外顺序」这条规矩(两处栽过,写在这儿别再踩)

两根线并排绕同一个障碍时(比如沿右板边下行、或贴上板边横过去),
**外面那根必须整条路把里面那根包在里面** —— 更早拐进、更晚拐出。
任何一处「里外交错」就是一个交叉。实测栽过两次:

- I2C 的 SDA/SCL 沿右板边下到 U1:SDA 在外(x=122.6 vs 123.5),
  所以 SDA 要更晚往东拐(y=10.8 vs 9.8)、更早往西拐(y=59.8 vs 63.6)
- U0TXD/U0RXD 贴上板边:U0TXD 在外(x=29.4),所以它要贴得**更靠板边**(y=1.15 vs 2.00)

### 第 9 条:Type-C 为什么要动摆位才布得通

Type-C 是可翻转的,D+/D−/VBUS 每个信号都有 A、B 两个触点,而且 A/B 是**交错**排在
同一排 0.5mm 间距的触点里(…B6 A7 A6 B7…)。同层怎么走都跨不过对侧的脚,只能换层;
换层要过孔,过孔要 1.01mm 的地方(0.6 直径 + 两侧 0.205)。**原来 R9/R10 正压在
触点正下方那个唯一的窗口上。**

所以:R10(CC2 下拉)挪到 (45,11.5)、R9(CC1 下拉)挪到 (59,13)、H3 挪到 (61,5),
把 y 9.7–14.3 整个空出来,再按**排好序的阶梯**出线 ——
四个脚先竖直下到 y=11.0(还是 0.5 间距,0.2 线宽刚好剩 0.3 的缝),
再斜着摊开到各自的过孔;过孔按 x 交替、y 分两层错开,任意两颗都隔得开。
VBUS 那一对走更浅的 y=10.9 底层横道,从 D+/D− 头顶过去。

另外**改过一次库封装**(这一轮唯一一处,原理图一个字没动):
`USB-C_SMD-TYPE-C-31-M-12_1.kicad_mod` 里 VBUS/GND 那四个自定义多边形焊盘原本
0.70mm 宽,和隔壁 0.30mm 的信号触点只隔 0.10–0.15mm(板厂下限 0.20,DRC 报 4 个错误)。
x 方向收到 0.75 倍(0.70 → 0.55),间隙变成 0.225–0.25。这里的 VBUS 只走 USB 编程
那点电流,每个网络还有两个触点,截面完全够。
| 9 | 全部元件顶层单面 | ✅ | ✅ 底面 0 个 |

## 七、丝印

- 每路端子:`CHn` + `V+ CW WW`;指示灯上方 `CW` / `WW`
- 进线:`24V IN` + `+` / `−`;`F1 ATO 15A`;脊椎带里一行 `F2-F7 4A T 32V`
- 接口:`USB-C PROG`(J2 右边、H3 下方)/ `SW1-4 + GND`(J11 下方)/
  `UART 5V`(J10 下方 y=10.6)/ `I2C 3.3V`(J9 下方)
  —— **这四条的 y 是照着渲染图逐个看出来的**:J10/J9 那两颗座子的塑料体比封装外框
  还往下探一点,按外框排会被本体挡住;`USB-C PROG` 挤在 R9/R10 之间会糊成一团。
- 端子位号 `J3`–`J8` **不在端子体正上方**(那儿是 `CHn` / `V+ CW WW`),
  由 `gen_pcb_v2.py` 显式放到相邻两列端子之间那道 4mm 的缝里 ——
  人类说的「丝印标号对不上」有一半就是这两拨字叠在一起
- 九个测试焊盘各自标网络名;板名 `cct-driver v2`
- ⚠️ **操作警示**:`24V MAX 12A - POWER OFF BEFORE UNPLUG J1` 写在 **J1 正下方的支撑带**里
  (那片是空板,插拔时眼睛正好看得到);下板边另有一句给六路灯带端子。
  **带电插拔那颗 24V 端子会拉火花烧触点**,这是人类 2026-08-15 确认的规矩。

### 位号

**位号的位置由 `gen_silk_refdes_fix.py` 生成,不要手改。** 判据是「到自己最近、且近出一截」:

    设 ds = 位号文字到**自己元件外框**的距离、do = 到**最近的其它元件外框**的距离,
    要求 do ≥ ds + max(0.20mm, 0.5×ds)。

**v2 的结果:歧义 0 处、被迫隐藏 0 个**(v1 是重摆 52 个 + 隐藏 4 个)。
做到这一点的关键是在**摆位阶段**就把丝印当硬预算:行距 ≥2.2mm,并且
**去掉无极性两端贴片件(0603/0805/1210/1206/2512)封装自带的装饰性丝印外框** ——
0603 的外框比 courtyard 大一整圈(2.93×1.47 vs 1.69×0.89),位号预算全被它吃掉。
有极性 / 有方向的件(LED、二极管、电解、IC、三极管、端子、保险丝座)**一个没动**。

### ⚠️ 上一版这一节写错了,错在哪里 —— 这是本项目最贵的一课

上一版这里写着「还差 9 条,其中 7 条是覆铜分片(电气上通,靠底层地平面),
只有 `RT_CLK` 和 `V24_BUS` 两条是真断路」。**这三句话有两句是错的:**

1. **`RT_CLK` 根本没断** —— 它一直是通的,这一节的记载过期了。
2. **`V24_BUS` 不是「被 V24_PROT 占掉那 2.7mm」** —— 真身是 U1 身上有**两只**
   同网脚(pad8 = IN−、pad9 = VBUS,间距 0.5mm),而生成器的 `PADXY` 每个
   (位号, 网络) 只存得下一只,另一只**谁都看不见**,就那么悬着。补一根 0.2mm
   的短线就完了。
3. **最要命的是那句「7 条是覆铜分片,电气上通」** —— 它对其中 5 片是对的,
   对另外几片是**错的**:那几片碎铜里正好夹着焊盘,而片上没有任何过孔和走线,
   **那几只脚是真的浮着的**。其中包括 ESP32 的 **EN 上拉电阻 R4** 和
   **上电延时电容 C12** —— EN 悬空,板子根本不会启动。DRC 一条错误都没报,
   因为它按 item 报未连接,读出来是「覆铜 GND ↔ 覆铜 GND」,像个记账问题。

**教训写成了检查,不是写成注释:`check-floating-pads.py`。**
判据:*碎铜里夹着焊盘却没有过孔和走线,那只脚就是浮的*。
它把焊盘 / 走线 / 过孔 / **每一片填充覆铜岛**都当成节点做真实几何碰撞
(`pcb_connectivity.py`),并查集出连通块,然后报三件事:

    ❌ 某块铜里只有焊盘和覆铜岛、没有走线也没有过孔  → 里面的焊盘是浮脚
    ⚠️ 某块铜里没有焊盘也没有走线、只有过孔          → 悬空过孔
    ⚠️ 一个网络的焊盘落在两块以上连通铜里            → 这个网络是断的

**每次改完布线都要跑,而且要全板跑。** 拿旧板回归验证过:它精确报出人工查了
半天才发现的那四只脚,一只不多一只不少。对全板跑,又揪出 14 只没人报过的,
其中一处同级严重:**buck 的七颗去耦(C32–C37)加 R62 的地脚自成一个封闭小世界**,
R62 是振荡电阻,它的地一浮 buck 就没有基准。

### 这一轮怎么清零的(三处根因,三种改法)

| 根因 | 症状 | 改法 |
|---|---|---|
| **顺序** | 救援连线排在 `run_todo()`/`chain()` 之后,等 EN 和 3V3 的短线落完笔,SW2 那只地脚已经三面封死(0.05mm 细网格洪水填充量过:可达区就是 x 13.25–14.45 / y 30.25–33.45 一个封闭口袋) | 把地脚救援挪到 `run_todo()` **之前**。地脚的活路只有零点几毫米宽,**谁先落笔谁占着** |
| **粒度** | `maze()` 的 0.25mm 网格会漏掉比 0.25mm 窄的走廊 —— 格点正好都落在障碍上 | `maze()` 加 `grid` / `win_margin` 两个参数:先按 0.25mm 试,不行退到 **0.05mm 细网格**,只在两端外扩 4mm 的窗口里搜(全板 0.05mm 是 850 万格,搜不动) |
| **摆位** | C46 整个人躺在 24V 脊椎当中,**两只脚都埋在 24V 铜里**;GND 那只脚顶层 4.36mm² + 底层 0.19mm² 两小片挖空区,和主地平面在两层上都没有重叠 | 转 90° 骑在脊椎**北**沿上:V24_BUS 那只脚留在脊椎铜里直接贴上去,GND 那只脚落进北边那片地,回路 <3mm。**拿一根 GND 线横切脊椎是不行的 —— 那是给 12A 母线开口子** |

另外 `gen_gnd_stitch.py` 加了**第二趟**:原来的判据是「岛里一颗地过孔都没有 → 补一颗」,
它漏掉一整类 ——「岛上明明有过孔,过孔在对面层接住的却是另一块同样孤立的铜」。
第二趟改成按真实连通块判:最大那块当主体,逐个孤立块找一个同时落在
「孤立块某一层的铜」和「主体在另一层的铜」里的落点,一颗过孔并起来。
并不上的**逐块列名、并列出里面困着哪几只焊盘**,不在那儿糊。
第一趟的面积门槛(<1mm² 一律跳过)也改了:**岛里夹着焊盘就无论多小都要试**。
